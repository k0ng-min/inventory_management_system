# ELECTRO ERP 요구사항 대조 분석

지시받은 요구사항 문서를 현재 구현과 1:1로 대조한 결과입니다.
분류는 **A 이미 구현 / B 기존 확장 / C 신규 / D 우선순위 낮춤**입니다.

## 현재 시스템 실측

| 항목 | 수치 |
|---|---|
| 코드 | 10,237줄 (백엔드 4,243 · 프론트 4,461 · 나머지 설정) |
| DB 테이블 | 27개 |
| API 라우트 | 90개 |
| 업무 화면 | 36개 |
| 외부 소스 어댑터 | 7개 (자재몰 수집·네이버·쿠팡·알리·나라장터 입찰·나라장터 쇼핑몰·계약공급처 REST) |
| 스모크 테스트 | 158개 전항목 통과 |
| 외부 런타임 의존성 | 0개 (Node 22 내장 모듈만) |

핵심 발견: **요구사항의 뼈대는 이미 서 있습니다.** `catalog_products`(정규화 제품)
+ `supplier_products`(공급처별 판매조건) + `price_history`(가격이력) 3층 구조와
`catalog.mjs`의 종류별 규격 파서가 Priority 1~4·6~7의 기반입니다.
비어 있는 곳은 **여러 제품을 나란히 비교(P5)** 와 **견적 리스트(P8)**, 그리고
**가격이력을 화면에 보여주는 층**입니다.

## Priority별 판정

| # | 요구사항 | 판정 | 근거 / 할 일 |
|---|---|---|---|
| 1 | 전기자재 통합검색 | **A·B** | `search.mjs` + `pur.search` 화면 존재. 검색어를 규격 파서에 태워 찾음. **B**: 결과 행에 과거 구매가가 없어 펼쳐야 보임 → 행에 직접 표시 |
| 2 | 전기 규격 구조화 | **A** | `CATEGORIES` 9종(cable·breaker·conduit·panel·wiring·terminal·tool·consumable·etc), 종류별 파서·keyFields·specLabel 구현 |
| 3 | 동일/유사 상품 매칭 | **A·B** | `spec_key` 동일성 매칭 + `confidence`(1/0.5/0) 신뢰도. **B**: 저신뢰 건을 사람이 검수하는 큐 화면이 없음 |
| 4 | 여러 공급처 가격 비교 | **A** | 제품 행을 펼치면 공급처별 단가·환산단가·납기·최소수량·가격구분 표. 최저가·최단납기 배지 |
| 5 | 제품 비교 | **C** | 현재는 제품 1개의 공급처 비교만. **여러 제품 체크 → 나란히 비교 + 차이 강조**가 없음 |
| 6 | 과거 구매가격 | **B** | `lastPurchase()` 있고 펼친 화면에 한 줄로 나옴. 요구사항의 `현재가/지난가/변동액/변동률/마지막구매일/구매처` 블록으로 승격 필요 |
| 7 | 가격이력 | **B** | `price_history` 테이블·`priceTrend()` API 있음. **화면에서 전혀 쓰지 않음**(그래프 미표시). `spark()` 함수는 이미 있음 |
| 8 | 견적 비교 | **C** | 여러 자재를 담는 구매 리스트, 업체별 합계(단가·수량·배송비·VAT·총액·납기) 비교가 없음. **이번 요구사항의 가장 큰 공백** |
| 9 | 구매요청 | **A** | 제품·규격·수량·단가·공급처·희망납기·요청자·비고 기록. 선택한 판매조건(`supplier_product_id`)까지 보존 |
| 10 | 승인 | **A** | 구매요청 → 승인 → 발주 1단 결재. `audit_logs`에 승인 기록 |
| 11 | 발주 | **B** | 존재하나 **1발주=1품목**. 견적비교(P8)가 여러 품목을 한 업체로 묶는 구조라 다품목 발주서로 확장 필요 |
| 12 | 입고 | **A·B** | 부분입고·입고예정 차감·매입전표 자동기표까지 됨. **B**: 불량/오배송 기록 필드 없음(비고만), 다품목 발주 입고 대응 |
| 13 | 사업장 재고 | **B** | 재고현황 화면 있음. 창고 필터 기본값이 전체라 조회는 문제없으나, **입고·이동·조정·배정에서 창고를 매번 고르게 함** → 기본 사업장 자동 선택 필요. 최근구매가·최근구매처·최근입고일·최근사용일 열 없음 |
| 14 | 출고/공사사용 | **A** | `project_allocations` 배정 → 출고, `moveStock()`이 수불 기록 |
| 15 | 재고 변동 이력 | **A** | `inventory_transactions`에 언제/누가/왜/몇개/잔량 전부. 재고수불부 화면 존재 |
| 16 | 부족재고 → 가격비교 | **A·B** | 재고현황 `구매` 버튼 → 판매처 비교 패널 → 구매요청까지 연결됨. **B**: 부족수량 자동 입력은 되나 통합검색으로 규격을 넘기는 경로는 없음 |
| 17 | 대시보드 | **B(충돌)** | 현재는 KPI 6장 + 매출 기준선 + 창고별 재고자산 = 전통 ERP형. 요구사항은 **큰 검색창 + "오늘 확인할 항목"**. 충돌 → 요구사항 우선 |

## 요구사항 문서의 개별 항목

| 항목 | 판정 | 내용 |
|---|---|---|
| 5. 외부 판매처 통합 | **A·B** | 어댑터 7개 존재(`SupplierAdapter` 역할). **B**: `VAT` 필드 없음(현재 배송비만), 어댑터 등록부가 코드에 흩어져 있어 신규 추가 시 4곳을 고쳐야 함 |
| 6. 카테고리별 Specification Schema | **A** | `CATEGORIES[*].fields` 가 그 역할. Cable/Breaker/Conduit/Terminal/Wiring 전부 정의됨 |
| 7. 확인 필요 상태 | **A·B** | `confidence < 1` → 화면에 `규격 확인 필요` 배지. **B**: 검수·확정 화면 없음 |
| 20. UI/UX | **B** | 디자인 시스템(토큰·그리드·컨트롤) 유지. Drawer(`openPanel`)·Modal(`openForm`)·펼쳐보기·상태 배지 이미 있음. 큰 검색창은 검색화면에만 있고 홈에 없음 |
| 21. 사용자와 권한 | **B(충돌)** | 현재 4역할 = admin/purchasing/warehouse/viewer. 요구사항의 **회계담당자 역할이 없음**(회계·매출은 admin 전용). 또 **가격이력·가격급등 API가 `requireFinance`(admin)** 라서 구매담당이 과거 구매가를 못 봄 — 요구사항 9와 정면 충돌 |
| 22. 기존 데이터 Import | **B** | CSV 적재(`ingest.mjs`, 헤더 자동 매핑, 미리보기, 적재이력) 완성. **품목·공급처 단가만** 지원 — 거래처 Import 없음. 엑셀(.xlsx) 직접 업로드 아님 |
| 23. AI 기능 | **A** | 규격 자동 추출·동일상품 매칭을 **규칙 기반 파서**로 구현. 결정은 사람이 함. 요구사항 "AI가 목적이 되면 안 된다"에 이미 부합 — LLM 추가 불필요 |
| 24. 참고 사이트 | — | Kojo의 핵심(이전 구매가·견적 비교·가격변동)이 P5~P8에 해당. CableStock의 Excel Export는 전 화면 CSV 내보내기로 이미 있음 |

## 우선순위를 낮출 것 (D — 삭제하지 않음)

| 기능 | 현재 위치 | 조치 |
|---|---|---|
| 재고이동(창고 간) | 재고 모듈 | 단일 사업장이면 쓸 일이 없음. 메뉴 하위로 내리고 창고가 2개 이상일 때만 노출 |
| 창고등록 | 재고 > 기준정보 | 유지. 기본 사업장 1개를 자동 생성·자동 선택 |
| `bin`(위치) 열 | 재고현황·입고 | 입력 강제하지 않음. 열은 유지 |
| 회계(전표·자금현황) | 회계 모듈(admin) | 매입전표 자동기표는 유지. 메뉴 우선순위 낮춤 |
| 영업(매출·수금) | 영업 모듈 | 구매·재고가 핵심이므로 노출 우선순위 낮춤 |
| 입찰(나라장터) | 입찰 모듈(admin) | 요구사항에 없음. 삭제하지 않고 admin 전용 유지 |
| 분석(구매·재고·공사수익) | 분석 모듈(admin) | 유지, 우선순위 낮춤 |
| Zone/Rack/차량재고 | 미구현 | 만들지 않음 |

## 충돌 판정 (요구사항 우선)

1. **대시보드 구성** — 기존 KPI 6장 → 상단 큰 검색창 + "오늘 확인할 항목"으로 재구성. 기존 KPI는 삭제하지 않고 아래로 내림
2. **가격 열람 권한** — `requireFinance`(admin 전용)였던 가격이력·가격급등을 **구매담당도 열람**으로 변경. 근거: 요구사항 9가 과거 구매가를 구매 판단의 핵심으로 규정
3. **발주 1건=1품목** — 견적비교(P8)가 다품목 묶음을 전제하므로 헤더+라인 구조로 변경
4. **창고 선택 강제** — 입고·조정·배정에서 기본 사업장 자동 선택으로 변경

## 구현 순서

요구사항의 Priority 순서를 따르되, 같은 코드를 두 번 만지지 않도록 묶었습니다.

| 단계 | 내용 | 해당 Priority |
|---|---|---|
| 1 | 가격이력 노출 층 — 검색 결과 행에 과거 구매가/변동률, 제품 상세에 추이 그래프, 가격 열람 권한 조정 | 6, 7 |
| 2 | 제품 비교 — 체크박스 다중선택 → 비교 화면, 차이 강조 | 5 |
| 3 | 견적함 + 업체별 견적 비교 (한 업체 일괄 / 품목별 최적) | 8, 11 |
| 4 | 다품목 발주서 (헤더+라인) + 인쇄 양식 + 라인별 입고 | 11, 12 |
| 5 | 단일 사업장 기본화 + 재고현황에 최근구매가·구매처·입고일·사용일 | 13 |
| 6 | 대시보드 재구성 (큰 검색창 + 오늘 확인할 항목) | 17 |
| 7 | 규격 검수 큐 · 거래처 Import · 불량/오배송 기록 | 3, 12, 22 |

각 단계는 스모크 테스트를 함께 늘리고, 158개 기존 항목이 계속 통과하는 것을 확인합니다.
