# 재고 기반 판매처 비교·구매요청

## 목표

재고현황에서 부족 수량을 확인한 사용자가 화면을 옮기지 않고 판매처별 가격·납기·가격 성격을 비교한 뒤, 선택한 조건으로 기존 구매요청 → 승인 → 발주 흐름을 이어 간다.

## 데이터 연결

- `products.catalog_product_id`가 사내 재고 품목과 정규화 카탈로그 제품을 연결한다.
- 기존 DB는 시작할 때 품명 규격을 다시 해석해 연결 열을 보정한다.
- 새 카탈로그 제품을 먼저 구매하는 경우 구매요청 생성 시 사내 품목을 한 번만 만들고 재사용한다.
- `supplier_products.price_basis`는 `retail`(시세), `contract`(계약), `quote`(견적)를 구분한다.
- `product_url`은 공급처 원문 확인용 HTTP(S) 주소이며, 화면에서는 안전한 주소만 연다.

## 업무 흐름

1. 재고현황의 `구매` 버튼을 누른다.
2. 연결된 카탈로그의 활성 판매조건을 환산단가순으로 조회한다.
3. 공급처, 가격구분, 판매단위, 단가, 환산단가, 납기, 확인일을 비교한다.
4. 판매처를 선택하면 부족 수량이 기본 입력된 구매요청 폼이 열린다.
5. 구매요청에 선택한 공급처·판매조건·단가를 보존한다.
6. 승인 화면은 그 공급처와 단가를 기본값으로 사용하고, 담당자는 필요하면 바꿀 수 있다.

## 오류·권한

- 구매 권한이 없는 사용자는 구매 버튼과 단가를 볼 수 없다.
- 판매조건이 다른 제품에 속하면 서버가 요청을 거부한다.
- 카탈로그 연결 또는 판매조건이 없으면 적재 화면으로 안내한다.
- 외부 상품주소는 `http://` 또는 `https://`만 허용한다.

## 검증

스모크 테스트는 카탈로그 ID로 구매요청 생성, 선택 공급처·단가 보존, 승인 발주 반영, 입고 후 통합검색 재고 연결까지 실제 API로 검증한다.
